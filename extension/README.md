# JobSeeker 크롬 확장 0.8.0

자동입력 확장(seungxa 0.7.0)과 지원 관리 팝업을 합친 확장이다.
- **자동입력은 확장 혼자 동작한다.** JobSeeker 서버나 웹이 꺼져 있어도 된다. 프로필은 확장 안의 아카이브(JSON 가져오기 또는 웹 Apply 페이지가 넘겨준 것)를 쓴다.
- **아이콘을 누르면 팝업이 뜬다.** 맨 위는 항상 **이 지원서 채우기**다.
- 지원 관리 연동(이 공고 저장, 오늘 할 일·다가오는 일정, 최근 지원 현황, 대시보드 열기)은 서버가 답할 때만 보인다. 서버가 없으면 빨간 오류 없이 접히고 안내 한 줄만 남는다. 로그인이 필요하면 로그인 버튼이 함께 보인다.
- 팝업의 **이 지원서 채우기**를 누르면 사이드 패널(자동입력)이 열리고 탭에 연결된다. 예전에 아이콘을 눌렀을 때와 같은 동작이다.
- 웹의 Apply 페이지가 로그인 토큰과 프로필을 확장에 넘겨준다.
- **설치:** 웹 Apply 페이지에서 zip을 내려받는다. 개발 중에는 이 폴더를 그대로 "압축해제된 확장 프로그램 로드"로 불러온다.
- **빌드:** `node scripts/practice-track/build-extension.mjs [--web-origin <팀 웹 주소>] [--api-url <API 주소>]`
- **구조·메시지·API·바꾼 파일:** [docs/practice-track/extension-contract.md](../docs/practice-track/extension-contract.md)
- **시험:**
  - `node --test tests/*.test.js`: seungxa 시험
  - `cd ../frontend && npx playwright test -c playwright.unit.config.ts`: 팝업·연결·빌드

## 자동입력 (JobSeeker Apply 0.7.0, seungxa)

규칙 기반 입력기(0.6.x) 위에 세 가지를 더했습니다.

1. **AI 판단 계층(선택)**: 규칙이 못 정한 항목만 AI에 묻습니다.
2. **범용 위젯 처리**: 토글·커스텀 드롭다운·검색 팝업을 다룹니다.
3. **사이트 구조 대응 확대**: div 레이아웃·iframe·Shadow DOM·숨긴 입력을 처리합니다.

AI를 끄면 이전처럼 규칙만으로 동작합니다.

### 설치

1. 기존 확장에서 아카이브를 JSON으로 내보냅니다.
2. chrome://extensions에서 기존 JobSeeker를 끕니다.
3. 개발자 모드에서 "압축해제된 확장 프로그램 로드"로 이 폴더(manifest.json 위치)를 선택합니다. 버전이 0.7.0인지 확인합니다.
4. JSON을 가져오고, 채용 페이지를 새로고침한 뒤 "현재 단계 채우기"를 누릅니다.

### 이번 버전에서 달라진 점

### 1. 항목 대응·값 형식 판단

- **규칙 단계(항상 동작)**
  - 입력칸 뒤에 "고등학교"·"대학교"·"학과"가 인쇄된 양식은 같은 계열 어미를 떼고 입력합니다. 예: `[동탄국제] 고등학교` ← 저장값 동탄국제고등학교 / 동탄국제고
  - 안내문의 "'고등학교' 제외", "'고'는 빼고", "예) 서울고등학교 → 서울" 같은 지시도 같은 방식으로 처리합니다.
  - 선택지는 동의어·같은 뜻 묶음으로 대응합니다. 예: 만기전역→군필, 해당없음→비대상, 남성→남, 2020→2020년, 서울→서울특별시
- **AI 단계(설정 시)**
  - 규칙으로 정하지 못한 항목만 한 번에 묶어 AI에 보냅니다. 예: 최종학력(대학교+졸업→대졸(4년)), "출신대학(약칭)", 처음 보는 항목명
  - 형식 안내가 있는데 규칙이 해석하지 못한 경우도 보냅니다.
- **AI 결과 검증**: 다음 경우만 입력하고, 나머지는 검토 목록에 제안값으로 남깁니다.
  - 아카이브에 실제로 있는 항목 경로
  - 저장값 그대로이거나 그 연속된 일부, 또는 같은 이름의 다른 표기(고↔고등학교)
  - 화면에 실제로 있는 선택지
  - 신뢰도 0.75 이상
- AI가 0.9 이상으로 연결한 항목은 사이트별 "저장한 연결"에 기록합니다. 다음 방문부터는 AI 호출 없이 처리합니다(값은 저장하지 않음).

### 2. 클릭·토글·팝업 검색

- **토글 버튼 묶음**: ARIA 없이 `on`/`active` 클래스로 상태를 표시하는 남/여 버튼 등
- **숨긴 라디오·체크박스**: display:none 입력을 보이는 label로 조작합니다.
- **select2·chosen·nice-select 등**: 숨겨진 원본 select를 설정한 뒤 보이는 상자 표시가 바뀌었는지 확인합니다. 바뀌지 않으면 보이는 목록을 열어 직접 고릅니다.
- **ARIA 없는 div 드롭다운**: 열렸을 때 새로 나타난 목록을 찾아 고르고, mousedown으로 열리는 위젯도 처리합니다.
- **검색 팝업**: 별도 창, `dialog`, 페이지 안 레이어, 레이어 안 iframe을 지원합니다.
  - 검색어는 원래 이름에서 시작해 줄인 형태(동탄국제고등학교 → 동탄국제고 → 동탄국제)로 차례로 시도합니다. 팝업에 "전기전자공학 → 전기" 같은 예시가 있으면 그 형식을 먼저 씁니다.
  - 결과는 정확히 같은 이름, 또는 캠퍼스·지역 표기만 다른 이름이 하나일 때만 규칙으로 고릅니다.
  - "컴퓨터공학과(야간)"처럼 비슷하기만 한 결과는 고르지 않습니다. 모든 검색어를 규칙으로 먼저 시도한 뒤에만 AI에 묻습니다.
  - 그래도 정하지 못하면 팝업을 열어 둔 채 직접 선택하도록 알립니다.
- **입력 중 클릭**: 이전 항목을 입력하는 중에 다른 칸을 클릭해도 무시하지 않고 대기열에 넣습니다.

### 3. 여러 사이트 대응

- **레이아웃 라벨**: `<div class="tit">학교명</div><div><input></div>`, `dt/dd`, 입력칸 앞 텍스트도 라벨로 읽습니다.
- **iframe**: 같은 단계 안의 iframe도 프레임별로 채웁니다. 권한이 없는 프레임은 결과에 주소를 알려 주므로 "현재 사이트 권한 허용" 후 다시 실행하세요.
- **Shadow DOM**: 열린 Shadow DOM(웹 컴포넌트) 안의 입력칸을 처리합니다.
- **검증 이벤트**: input/change와 함께 blur·focusout 이벤트를 보내 blur 시 검증하는 사이트에 대응합니다.
- **버그 수정**
  - 이메일 도메인 목록 인식 정규식이 잘못 이스케이프되어 "아이디 + 도메인 선택" 구조를 놓치던 문제
  - 표 머리글의 `*` 제거 정규식 오류

## 지원 관리 팝업

확장 아이콘을 누르면 뜨는 팝업입니다. ③ Track(지원 관리)으로 이어 주는 역할을 합니다. 서버에 연결되지 않으면 이 부분은 접히고 자동입력만 보입니다.

- **이 공고 저장:** 사용자가 **페이지 제목으로 채우기**를 누르면 보고 있는 채용 공고의 회사·직무·직무 분류를 제목 메타데이터로 추정해 채워 줍니다. 팝업을 열기만 해서는 페이지에 스크립트를 주입하지 않으며, 본문·자소서는 수집하지 않습니다. 확인 후 저장하면 지원 관리에 들어갑니다. "지원 완료"를 체크하면 지원일이 오늘로 기록됩니다.
- **이미 저장한 공고:** 같은 URL이면 현재 단계·상태를 보여 주고, 상세 보기로 바로 갈 수 있습니다. **지원 완료로 표시**를 직접 누르면 같은 URL의 지원 건에 `submitted: true`를 보냅니다.
- **최근 지원 현황:** 최근 5건과 전체·진행중·합격 수
- **대시보드 열기:** 웹 대시보드를 새 탭으로 엽니다.

### 설치(개발용)

1. 백엔드(`backend/`)와 웹(`web/`)을 먼저 실행합니다. 방법은 저장소 루트 README에 있습니다.
2. 크롬 주소창에 `chrome://extensions` 입력
3. 오른쪽 위 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램 로드** → 이 `extension-track` 폴더 선택
5. 퍼즐 아이콘에서 JobSeeker를 고정해 두면 편합니다.

백엔드·웹 주소가 다르면 팝업 오른쪽 위 **설정**에서 바꿉니다. 배포 주소로 바꿀 때는 `manifest.json`의 `host_permissions`에도 추가해야 합니다. 설정 화면은 저장한 API 주소가 `host_permissions`에 없으면 경고를 띄웁니다(백엔드 CORS가 `chrome-extension://`을 허용하므로 요청 자체는 되지만, 배포 주소는 두 곳을 함께 맞춥니다).

### ① Apply 확장과 합치는 방법

팝업만 독립적으로 동작하도록 만들어 두었습니다. ① 확장에 합칠 때는:

- `popup.html`, `popup.css`, `popup.js`, `api.js`, `extract.js`, `settings.js`를 ① 확장 폴더로 옮기고 `action.default_popup`을 `popup.html`로 지정
- `permissions`에 `activeTab`, `scripting`, `storage`, `host_permissions`에 백엔드 주소 추가
- ①이 지원서 제출을 감지하면 같은 `POST /track/sync`에 `essays`(문항·답변)와 `submitted: true`를 보내면 됩니다. 팝업에서 먼저 저장한 공고와 URL이 같으면 같은 지원 건으로 합쳐집니다.
- 로그인을 붙이는 쪽은 `settings.js`의 `setAccessToken(token)`으로 Supabase 액세스 토큰을 넣고, 로그아웃 때 `setAccessToken(null)`을 부릅니다. `api.js`의 `getToken()`이 이 값(`chrome.storage.session`, 브라우저를 닫으면 지워짐)을 읽어 `Authorization: Bearer`로 붙입니다. 토큰이 없으면 개발 모드(`AUTH_DISABLED=true`) 서버에서만 동작합니다.
- 토큰 수명주기 연결: 로그인 성공·토큰 갱신·계정 변경 때 `setAccessToken(nextToken)`, 로그아웃 때 `setAccessToken(null)`을 호출합니다. 팝업은 `chrome.storage.onChanged`를 받아 이전 계정의 목록·공고·진행 중 응답을 무효화합니다. 401은 HTTP 상태를 가진 `ApiError`로 유지하며, 해당 요청에 쓴 토큰만 삭제합니다(그사이 새로 갱신된 토큰은 보존).
- **다시 로그인** 버튼은 설정의 선택 항목 `팀 로그인 주소(loginUrl)`를 엽니다. 빈 값이면 설정 안내를 보여 줍니다. 이 저장소에는 공통 로그인 화면·로그인 완료 전달 브리지가 없으며, 실제 팀 로그인 담당자가 위 훅을 연결해야 합니다.
- 새 클라이언트는 `submitted`를 항상 명시합니다. 팝업 저장은 체크 여부의 boolean, 지원 완료 전환은 `true`, 문항 없이 저장할 때는 `essays: []`를 보냅니다. ① 확장은 사용자 승인 없이 본문·답변을 수집하거나 자동 전송하지 않습니다.
- 자동 테스트: `frontend/tests/practice-track/unit/extension.spec.ts`는 Chrome 저장소 대역으로 공고 추정·토큰 저장·주소 권한·명시 submitted·401 상태와 토큰 경합을 검사합니다. `frontend/e2e/practice-track/track-extension.spec.ts`는 팝업 DOM과 API·Chrome 대역으로 사용자 클릭 수집·기존 공고 제출 전환·401/재로그인·계정 전환을 검사합니다. 실제 Chrome 설치·권한·페이지 주입·Supabase/팀 로그인 연결은 검증하지 않았습니다.

### 회사·직무 추정 방식

`extract.js`가 `og:title`(없으면 `<title>`)을 읽어 `[회사] 제목`, `제목 | 회사 - 플랫폼` 같은 흔한 형식을 나눕니다. 사람인·원티드·잡코리아·LinkedIn 같은 플랫폼 이름과 "채용", "모집" 같은 꼬리말은 떼어 냅니다. 사이트마다 구조가 달라 틀릴 수 있으므로 저장 전에 사용자가 고칠 수 있게 했습니다.
