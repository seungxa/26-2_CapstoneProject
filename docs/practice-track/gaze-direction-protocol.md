# 시선 방향 실측: 3회 절차와 기록표

시선 방향 실험실(`/practice/dev/gaze-direction`)은 개발 전용 화면이다. 면접 회고에 시선 방향(정면·위·아래·왼쪽·오른쪽)을 보여 줄지 정하기 위해, 실제 웹캠으로 판정이 쓸 만한지 사람이 직접 잰다.
- 자동 테스트는 합성 얼굴로 계산과 흐름만 확인한다. 그 결과를 실제 정확도로 옮겨 적지 않는다.
- 설계: [2026-11-14-local-ai-gaze-direction-design.md](2026-11-14-local-ai-gaze-direction-design.md) 4.3절 C5.

## 실행

카메라가 있는 컴퓨터에서 직접 띄운다. 브라우저는 `localhost` 주소나 https에서만 카메라를 허락하므로, 다른 컴퓨터에서 띄운 화면에 접속하는 방식은 쓰지 않는다.

### 카메라가 있는 노트북에서 (권장)

실험실 화면만 띄운다. 로그인, 연습 서버, 파이썬이 필요 없다.

1. 준비물은 Git과 Node.js 22 이상뿐이다. 인터넷은 처음 한 번 얼굴 검출 모델을 받을 때 필요하다.
2. 처음 한 번만:
   ```
   git clone -b feature/local-ai-gaze-direction https://github.com/seungxa/26-2_CapstoneProject.git
   cd 26-2_CapstoneProject/frontend
   npm ci
   cd ..
   ```
   이미 받아 두었다면 저장소 루트에서 `git pull`만 한다.
3. 저장소 루트에서 `node scripts/practice-track/start-gaze-lab.mjs`를 실행한다. Windows 명령 프롬프트, PowerShell, macOS 터미널 모두 같다.
4. 같은 노트북의 크롬으로, 실행기가 알려 준 주소 `http://localhost:5181/src/features/practice-track/dev/gaze-lab.html`에 접속한다.
5. "Turn On Camera"를 누르고, 카메라 권한을 직접 허락한다.
6. 끝나면 실행기 창에서 Ctrl-C로 끈다. 실험실 결과는 화면을 떠나면 사라지므로, 먼저 집계를 복사해 둔다. 실행기가 처음에 보여 준 `Code:` 값을 기록표의 Git SHA로 적는다.

### 앱 전체와 함께 (카메라가 있는 개발 PC)

1. 저장소 루트에서 `scripts/practice-track/start-validation-pilot.sh`를 실행한다.
   - 로컬 인증 대역, 백엔드, 프런트를 새 임시 폴더로 띄운다.
   - 외부 유료 API는 쓰지 않는다.
2. 브라우저(Windows에서는 크롬)로 `http://127.0.0.1:5181/practice/dev/gaze-direction`에 접속한다.
3. 로그인에는 로컬 전용 계정 `practice@example.invalid` / `local-test-only`를 쓴다. 실제 계정은 쓰지 않는다.
4. "Turn On Camera"를 누르고, 카메라 권한을 직접 허락한다.
5. 끝나면 스크립트 창에서 Ctrl-C로 서버를 끈다. 실험실 결과는 화면을 떠나면 사라지므로, 먼저 집계를 복사해 둔다.

## 준비

- 화면에서 약 50~60cm 떨어져 평소처럼 앉는다. 평소 조명과 노트북 내장 카메라를 쓴다.
- 창을 고정하고 확대/축소를 바꾸지 않는다. 시험 중에는 다른 탭이나 창으로 옮겨 가지 않는다.
- 다음 경우 그 실행은 무효이고, 기록표에 넣지 않는다: 시험 중에 창 크기·위치·배율이나 카메라 해상도가 바뀜, 탭이 가려짐, 카메라 화면이 끊김.
- 아래 표의 "환경" 줄에 다음을 적는다: 카메라 모델, 브라우저·OS 버전, 카메라 해상도, 뷰포트, 배율, 안경 여부, 조명, 현재 Git SHA.
- 녹화, 화면 캡처, 얼굴 사진 업로드는 하지 않는다. 복사한 집계에는 영상·좌표·특징점이 들어 있지 않다. 집계에 개인 정보를 덧붙이지 않는다.

## 새 기준 잡기로 연속 3회

1. **"시험 시작"을 누른다.**
   - 먼저 약 10초 동안 점 다섯 개(가운데 → 위 → 아래 → 왼쪽 → 오른쪽)를 보며 기준을 잡는다.
   - "기준을 잡지 못했어요"가 나오면 사유를 읽고 "다시 하기"를 누른다. 실패한 기준 잡기는 횟수에 넣지 않는다.
2. **안내에 따라 점을 본다.**
   - "고개는 그대로, 눈으로만 점을 보세요": 고개를 움직이지 않는다.
   - "고개와 눈을 편하게 움직여 점을 보세요": 평소처럼 본다.
   - 마지막 대본 시행은 키보드 앞에 종이 대본이 있다고 생각하고, 화면 아래 너머(책상)를 5초 동안 읽듯이 본다.
   - 자연스러운 눈 깜빡임은 그대로 둔다.
3. **결과를 기록한다.**
   - 결과 화면에서 "집계 복사(JSON)"를 눌러 아래 "원본 집계"에 붙인다.
   - 표에 회차별 숫자를 옮긴다.
4. **다음 실행도 새 기준 잡기로 한다.**
   - "시험 시작"을 다시 누르면 기준을 새로 잡는다. 같은 기준으로 반복한 것은 독립 실행으로 세지 않는다.
5. **추가 실행(선택):** 3회가 끝난 뒤 안경과 저조도 중 **하나만** 바꿔서 1회 더 한다. 한 번에 여러 조건을 바꾸지 않는다.

## 판정 규칙

**한 번의 실행이 통과하려면 다섯 가지를 모두 만족해야 한다** (잠정 기준, `constants.ts`의 `DIRECTION_PASS`):

| 항목 | 기준 |
|---|---|
| 정면 정답률 | 85% 이상 |
| 아래 정답률 | 80% 이상 |
| 위·왼쪽·오른쪽 정답률 | 각각 70% 이상 |
| 정면을 아래로 오판 | 10% 이하 |
| 판정 못 함 | 15% 이하 |

- 판정 못 함은 정답으로 세지 않고 분모에 넣는다.
- 대본 시행의 '아래' 비율은 참고 값이고, 통과 판정에는 쓰지 않는다. 낮게 나오면 결과 화면의 "대본 읽기 구간의 판정 못 함 사유"를 함께 적는다. 고개를 숙여 '자세·거리 변화'가 많은지, '눈 감김'이 많은지 등으로 원인을 가린다.

**전체 판정:**
- 새 기준 잡기 3회 중 2회 이상 통과하면, 회고 화면에 시선 방향을 넣는 다음 단계(C2~C4)로 간다.
- 통과해도 정확도를 보장하는 것은 아니다. 한 사람, 한 기기의 결과다.
- 통과하지 못하면 시선 방향을 제품에 넣지 않는다. 실패한 항목과 판정 못 함 사유를 보고 기준값(`DIRECTION`)을 조정할지 함께 정한다. 기준값을 조정했다면 그 이전 실행과 수치를 섞지 않고 새로 3회를 잰다.
